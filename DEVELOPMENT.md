## Идея проекта

Компании, работающие с массовыми вакансиями, нуждаются в актуальной базе работодателей по отраслям. Ручной сбор данных с HeadHunter — долгий и рутинный процесс.

**HH-Parser** решает эту задачу: автоматически собирает базу компаний с hh.ru по выбранным индустриям, фильтрует по параметрам и выгружает результат в удобном формате.

## Этапы разработки

### Этап 1. Ядро парсинга

Первым делом было написано ядро системы — модуль `hh_companies_by_industry.py`.

**Что реализовано:**
- Загрузка каталога индустрий с hh.ru
- Обход всех страниц пагинации выбранной индустрии
- Парсинг HTML — извлечение названий компаний, ссылок и количества вакансий
- Фильтрация по минимуму вакансий, региону, наличию открытых вакансий
- Дедупликация компаний по URL
- CLI-интерфейс для интерактивной работы из терминала
- Экспорт результатов в JSON

**Технологии:** Python, requests, BeautifulSoup4, lxml

---

### Этап 2. Desktop GUI

Для удобства конечных пользователей был разработан графический интерфейс.

**Что реализовано:**
- Полноценное десктопное приложение на Flet (кроссплатформенный фреймворк на базе Flutter)
- Загрузка и отображение списка индустрий с поиском
- Настройка фильтров через UI
- Прогресс-бары для отслеживания процесса парсинга
- Экспорт в CSV и JSON
- Выбор папки сохранения (с автоопределением Рабочего стола, включая русскую локаль)
- Сборка в standalone-приложение через PyInstaller (Windows + macOS)
- Windows-инсталлятор через Inno Setup

**Технологии:** Flet, PyInstaller, Inno Setup

---

### Этап 3. Повышение надёжности

Парсинг внешних сайтов — процесс ненадёжный по своей природе. На этом этапе система была укреплена.

**Что реализовано:**
- **Retry с экспоненциальной задержкой** — при ошибках сети или блокировках (HTTP 403/429) система автоматически повторяет запросы до 3 раз с нарастающей паузой
- **HHBlockedError** — специальное исключение с понятным сообщением для пользователя при блокировке со стороны HH
- **Логирование** — все retry-попытки и ошибки логируются для диагностики
- **Единая версия проекта** — `__version__` в одном месте, импортируется во все модули

---

### Этап 4. Тестирование

Для защиты от регрессий были написаны юнит-тесты на все ключевые функции парсинга.

**Покрытие (18 тестов):**
- `with_query()` — формирование URL с query-параметрами
- `extract_max_page()` — определение количества страниц пагинации
- `parse_industries()` — парсинг списка индустрий из HTML
- `parse_companies_from_industry_page()` — парсинг компаний со страницы индустрии

Тесты работают на статичном HTML — не зависят от сети и не нагружают hh.ru.

**Технологии:** pytest

---

### Этап 5. Веб-версия

Для доступа к парсеру без установки приложения была разработана веб-версия.

**Что реализовано:**
- **FastAPI-бэкенд** — REST API для загрузки индустрий, запуска парсинга и выгрузки CSV
- **SSE (Server-Sent Events)** — real-time стриминг прогресса парсинга в браузер
- **Лендинг** — адаптивный интерфейс с тёмной темой:
  - Выбор индустрий с поиском и массовым выделением
  - Настройка фильтров
  - Лог парсинга в реальном времени (терминальный стиль с таймстампами)
  - Комбинированный прогресс-бар
  - Таблица результатов с сортировкой
  - Скачивание CSV
- **Кэширование** — список индустрий загружается один раз и кэшируется

**Технологии:** FastAPI, Jinja2, SSE, HTML/CSS/JS

---

### Этап 6. Деплой

Проект подготовлен к production-деплою.

**Что реализовано:**
- **Dockerfile** — контейнеризация приложения
- **amvera.yml** — конфигурация для автодеплоя на платформе Amvera
- Деплой через `git push` — любое обновление кода автоматически пересобирается и разворачивается
- **CI/CD через GitHub Actions** — автоматическая сборка desktop-версий для Windows и macOS при создании тега

**Технологии:** Docker, Amvera, GitHub Actions

## Ключевые решения

| Решение | Почему |
|---------|--------|
| Отдельное ядро парсинга | Один модуль используется тремя интерфейсами (Web, GUI, CLI) без дублирования кода |
| SSE вместо WebSocket | Проще в реализации, достаточно для однонаправленного стриминга прогресса |
| Retry с экспоненциальной задержкой | HH периодически блокирует частые запросы — retry решает большинство случаев автоматически |
| Flet для десктопа | Кроссплатформенность из коробки, Python-нативный, быстрая разработка UI |
| Docker + Amvera | Простой деплой через `git push`, не нужно настраивать сервер вручную |
| pytest на статичном HTML | Тесты не зависят от сети и разметки hh.ru — стабильные и быстрые |

## Результат

- **3 интерфейса** для разных сценариев использования
- **18 юнит-тестов** на критичные функции
- **Автодеплой** — обновление продакшена одной командой `git push`
- **Real-time мониторинг** парсинга в веб-версии
- **Устойчивость** к блокировкам и ошибкам сети
